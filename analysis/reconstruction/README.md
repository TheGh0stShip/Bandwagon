# Binary-exact assembly evidence

These files are real GNU-style PowerPC assembly accepted by LLVM's assembler.
They are byte-preserving evidence reconstructions, not a substitute for the
readable source-level recovery tracked in `SOURCE_RECOVERY.md`, and not the
unpublished Peer Pressure original source. Names are derived from proved
behavior; unresolved meanings remain labeled `unknown` or `hypothesis`.

## Stage4

`PeerPressureExploit-4thStage.reconstructed.S` rebuilds the complete 67,456-byte
Peer Stage4 file byte-for-byte, including its resident functions, patch
records, copied HV code, structured data, padding, and the exact public
BadUpdate clean-HV tail. The clean tail is included from the already verified
local public Stage4 artifact rather than duplicated.
The portable `reconstruction/stage4/rbtr_dispatcher.*` layer models the
resident dispatch table and argument transformations without performing live
hypervisor operations.
The complete Peer-authored preamble also has C++/typed-data coverage under
`reconstruction/stage4/`; its whole-file source/ownership partition is checked
by `tools/verify_stage4_source_coverage.py`.

## Stage3

`PeerPressureExploit-3rdStage.reconstructed.S` rebuilds the complete 5,600-byte
Stage3 file byte-for-byte. The entry point and Peer-specific probe are
hand-labeled assembly. Remaining code regions are deterministic LLVM assembly
generated by `tools/recover_ppc_region.py`; strings and non-code data are
emitted as literal bytes. The application routines now have complete
source-level coverage through Peer C++ plus the pinned public BadUpdate
sources, verified by `tools/verify_stage3_source_coverage.py`.
The portable `reconstruction/stage3/resident_probe.*` layer additionally
models the now-resolved dual resident-dispatcher protocol without executing
hypervisor calls.

## Persistent HDD Stage2

`PeerPressureExploit-Stage2.reconstructed.S` rebuilds the entire 217,796-byte
HDD ROP image, embedded relocated worker, strings, and trailer descriptor.
`tools/reconstruct_hdd_stage2.py` generates the assembly and 87-entry worker
map. The common reconstruction verifier now checks Stage2, Stage3, and Stage4
as complete files.

`HddSecuritySectorPayload.reconstructed.S` is the exact six-word HDD trigger
record. Its known retail-17559 stack-pivot word and unresolved kernel pointers
are documented without speculative names.

## Verification

Run:

```sh
python3 -B tools/rebuild_peer_reconstructions.py
```

The verifier assembles for `powerpc64-unknown-linux-gnu`, extracts `.text`, and
compares the entire Stage3 and Stage4 outputs. It never executes an Xbox binary
or reconstructed payload.

## Updater

`Updater.text.reconstructed.S` rebuilds all 88,640 bytes of Updater's PowerPC
`.text` section exactly. It carries labels for the 376 boundaries recovered by
the pinned jeff analysis. `tools/reconstruct_xex_text.py --check` independently
regenerates the assembly and enforces byte identity against the extracted PE
image. `Updater.nontext.reconstructed.S` additionally rebuilds the initialized
`.rdata`, `.pdata`, and `.data` virtual ranges byte-for-byte; verify those with
`tools/reconstruct_xex_nontext.py --check --verify-bytes`.

The portable C++ in `reconstruction/updater/bootstrap_record.*` is the first
reviewable high-level replacement extracted from the Updater. It reconstructs
the record-building half of `InstallHddBootstrap` without exposing host raw-disk
I/O. The original binary writes uninitialized final-sector padding; the open
replacement intentionally zeroes that padding and tests the deviation.

## BootXell

`BootXell.text.reconstructed.S` rebuilds all 74,840 bytes of the OtherOS
launcher's initialized code, while `BootXell.nontext.reconstructed.S` rebuilds
its `.rdata`, `.pdata`, and `.data` ranges. `tools/analyze_bootxell_xex.sh`
regenerates both sources and their function, call, and string-reference maps.

## AuroraFixer

`AuroraFixer.text.reconstructed.S` and
`AuroraFixer.nontext.reconstructed.S` exactly rebuild every initialized code
and data section in the compatibility DLL. The portable C++ under
`reconstruction/aurora_fixer/` reproduces its four-instruction absolute branch
encoder without performing live memory writes.

## UpdateCheck

`UpdateCheck.text.reconstructed.S` and `UpdateCheck.nontext.reconstructed.S`
exactly rebuild all initialized code and data in the HTTPS release checker.
`tools/analyze_updatecheck_xex.sh` regenerates the sources and its function,
call, and string-reference inventories.

## BootEdit

`BootEdit.text.reconstructed.S` and `BootEdit.nontext.reconstructed.S` exactly
rebuild the initialized code and data of the `.xbat` theme editor. Its generated
maps and sources are regenerated by `tools/analyze_bootedit_xex.sh`.

## SettingsApp

`SettingsApp.text.reconstructed.S` and
`SettingsApp.nontext.reconstructed.S` exactly rebuild every initialized code
and data section in the main settings UI. Use
`tools/analyze_settingsapp_xex.sh` for deterministic regeneration.
